# 相对已有 ASU 图粒度的增量收益

## Material Passport

2026-09-08；Slurm 533539 / A100-SXM4-80GB；队列012成功；固定拓扑模型组件实验，没有训练或生成晶体。协议为 `ASU_CONTROL_PROTOCOL.md`。

对照按 coGN 官方构图所采用的逐邻居 ASU 图粒度实现，但使用我们与候选共同的径向网络。这是控制变量实验，**不是 coGN 原架构成绩的复现**。

## 结果

三个路径共享参数构造器与权重。FP64 的32图检查与 FP32 的512图检查中，clean及WP切空间扰动下的图级特征、代表处向量输出、坐标梯度和参数梯度全部通过既定容差。两种 ASU 路径的节点相同，差别只在邻居边是否按轨道汇总。

| 批次 | 指标 | ASU逐邻居图 | 边轨道图 |
|---|---|---:|---:|
| 32图 | 节点数 | 154 | 154 |
| 32图 | 有向边/边类别 | 3769 | 1826 |
| 32图 | 前向+反向中位数 | 5.993 ms | 6.418 ms |
| 32图 | 峰值分配内存 | 43.33 MB | 30.96 MB |
| 512图 | 节点数 | 2390 | 2390 |
| 512图 | 有向边/边类别 | 53212 | 26894 |
| 512图 | 前向+反向中位数 | 6.165 ms | 6.888 ms |
| 512图 | 峰值分配内存 | 390.86 MB | 216.63 MB |

MB为十进制，内存为PyTorch CUDA allocated peak。四轮交替顺序，每轮预热3次后测量10次前向+反向；不含在线构图成本。

- 32图：边轨道路径额外减少28.6%内存，但慢约7.1%。
- 512图：额外减少44.6%内存，但慢约11.7%。

之前相对原胞完整图的1.57倍提速包含已知的ASU节点约简收益。这里隔离新增边合并后，实测为**显存—耗时权衡**，不能继续把更快作为相对ASU方法的优点。

## 可以与不可以得出的结论

可以确认：在已测试的网络与固定拓扑条件下，按边轨道汇总可在保持输出与梯度一致的同时，显著减少激活内存。时间优势未出现；额外的方向和与加权运算抵消了减少消息条数的速度收益。

未确认：训练后的生成质量、完整扩散总耗时、动态邻接、跨空间群/晶格变化和更大模型的资源收益。实际离散边token生成尚未实现。

文献边界：ASU节点和仿射边已存在；官方构图逐条保留邻居边。当前实现的实质变化是进一步合并边轨道并计数加权。这个有限差别不能自动变成“新的条件扩散tokenizer”结论。

## 下一步应解决的表示问题

现有codec头部仍包含连续ASU坐标。如果希望它承担“prototype先生成、再生成几何”的作用，需要把节点的标准位点约束与自由几何参数分开：用离散的仿射site-stabilizer/所在Wyckoff分支定义位置族，边保留operation+translation标签；自由坐标和晶格放在几何载荷中。

应首先检查：移除真实自由坐标后，离散prototype是否仍能定义同一个周期连接图（允许原子编号和晶胞像选择的等价变化）。该验证若不能通过，当前方案就只适合作为给定几何下的计算压缩，不能当作所需prototype tokenizer。

数据与代码摘要：`graph_backbone/asu_control.json`；之前较弱基线的结果保留在 `GRAPH_BACKBONE_RESULTS.md`，本文件优先说明新增边压缩的收益。
