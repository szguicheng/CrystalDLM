# 固定权重的释放顺序诊断

依据：recovery_001混合联合后的128验证G3、闭环2，参考读取128、编辑76；第一批旧64 G0，新64 G3。语言恢复但生成仍受边界及字段错误限制。先检查采样顺序，而不是继续盲目增加训练或修补CIF。

使用最终混合联合checkpoint（512更新），先按ID哈希固定16训练材料、原验证前16、原fresh64前16，共48材料；后者现在已经做过模型验证，不能再称本诊断的新未见验证。每材料seed17/29/43，随机/置信度两策略，总288次生成尝试，全部留分母。只测生成，不把该诊断当闭环或最终测试。

每种子先抽取共同释放数量：当前剩余N个MASK、时间k，抽Binomial(N,1/k)，最后k1全部释放。两策略每步数量完全相同；随机在剩余位置均匀选取，置信度按模型对实际抽中token的未温度缩放概率排序。温度均0.8、容量256、32步、同一AR触发语及参数；已经释放的token不可改。随机控制与原吸收过程同分布，但随机数映射不同，故不能用其seed单样本去逐位复现原主评估。

参考[LLaDA官方采样代码](https://github.com/ML-GSAI/LLaDA/blob/main/generate.py)的模型概率排序。这里不是完整复现LLaDA：模型、共同Binomial释放数量及晶体任务不同；不使用EOS禁用或结束logit加成等选项。置信度顺序是启发式变体，不声称它仍为精确的随机逆核。

只改变被释放的位置；不修改token抽样值，不输入真实长度，不确保END/PAD唯一，不代填组成、SG、坐标或边长，不失败重试。原主采样、检查点及结果保留。输出原始串、每步位置/数量、审计、模型前后指纹，确保零更新。test256不读。

在已分配计算节点用独立Slurm步骤运行。若与AR训练共享GPU，训练计时受争用影响；质量诊断不能证明速度收益。任何有用信号均需随后在完整验证队列检验，不能挑选本诊断的成功样例当完成目标。
