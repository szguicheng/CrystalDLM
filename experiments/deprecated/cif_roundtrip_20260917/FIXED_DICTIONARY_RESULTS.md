# 固定字典版本：转换与 token 数量

已将每份材料重复携带的全局操作表、Wyckoff 位点约束、自由度移至只读共享字典。材料序列引用 global rule ID 和 site rule ID。字典内没有元素、晶格参数、自由坐标、材料 ID 或边列表。

字典：9 套全局规则、25 种位点规则，文件 14,919 字节。本批十个案例的符号规则先建表、再冻结，未声称覆盖全部晶体或验证未见规则泛化。
测试在 Burgundy CPU / Slurm 568611 完成，10/10 从原始 CIF 编码为纯文本序列、独立进程解码回 CIF，并重新编码得到逐 token 相同的序列。元素、晶格、坐标、边集合均通过检查。字典字节始终不变，未知规则和错误字典版本均被拒绝。

## KrF₂ 的直接结果

**原始 CIF 59 → 完整边轨道序列 62 → 恢复 CIF 59。**

旧版本结构字段 401 个，固定字典版本结构字段 57 个，另有 5 个必要的格式/计数头部单元，实际文件共 62 个单元。以下每个数值或标签计一个，不计空白，不使用 BPE：

| 内容 | 数量 |
|---|---:|
| 全局规则 ID | 1 |
| 晶格矩阵 | 9 |
| 两个位点的元素与位点规则 ID | 4 |
| 独立自由参数 | 1 |
| 七条边，每条六个整数 | 42 |
| 格式版本、字典版本、位点数、边数、半径 | 5 |
| 合计 | 62 |

原来的六个自由向量分量缩为一个独立参数：Kr 位点没有自由参数，F 位点只需要一个，其余分量由固定约束恢复。

## 字典成本与边界

十份序列合计 7,159 字节，加上只需保存一次的 14,919 字节字典，共 22,078 字节。这是规则表＋材料文本序列的大小，不是输出包或运行环境大小。
相同空间群在不同基底/原点下可能需要不同规则条目。编码遇到字典没有的规则会报错，需要在独立建表步骤显式更新并冻结新版本，不会根据待解码材料临时补齐。
沿用上一轮严格数值对称识别：5 个案例的识别群低于数据集标签，其中一个为 P1。这一限制没有通过本次共享字典消除。

## 使用

```bash
python fixed_dictionary.py encode results/mp-30009/input.cif my.tokens --dictionary fixed_dictionary_results/rules.json
python fixed_dictionary.py decode my.tokens restored.cif --dictionary fixed_dictionary_results/rules.json
```

解码只依赖序列和共享规则字典。完整语法、建表命令和验证方法见 README.md。
