# NatureCry：Kimi 自然语言编解码的 100-case 结果

2026-10-02。模型为 SciencePal `tokenhub/kimi-k3`，文字由 LLM 自由组织，解码使用独立请求。
主指标为恢复晶体与原始输入晶体的严格匹配；改写、空间关系编辑和训练均未执行。

阶段状态：**初步验证完成**。按用户确认，以“自然语言编解码＋验证筛选”的初步可行性作为阶段结论，保留合格配对、丢弃失败配对，不要求所有 case 都成功。下面的首次实测结果保持原样；NatureCry 训练与训练收益验证留待后续讨论。

## 主结果

**冻结的 100 个 case 首次流程通过 84 个，失败 16 个，通过率 84%。**
没有更换样本、自动重试、补写描述、修复计划或降低容差。

| 结果类别 | case 数 |
|---|---:|
| 恢复原晶体，满足全部严格要求 | 84 |
| 请求连接中断 | 3 |
| decoder JSON 外层格式导致解析失败 | 1 |
| 几何执行/约束校验失败 | 6 |
| 构造完成但与原晶体数值不匹配 | 6 |

3 个连接失败没有完成模型链路，不能当作模型语义错误。
另外 97 个完成传输的 case 中，84 个首次通过，比例为 86.6%；主结果仍以全部 100 个冻结 case 为分母。

通过标准：保持输入晶胞，元素计数和原子数完全相同；同元素周期性一一匹配的最大坐标误差 `< 1e-6 Å`，晶格矩阵分量误差 `< 1e-8 Å`。
84 个通过样例的最大坐标误差为 `9.3814e-16 Å`，最大晶格分量误差为 `3.0198e-14 Å`。
验证对象为实际写出并重新解析的 CIF，不以自然语言看起来合理代替结构匹配。

## 样本和接口

沿用固定格式程序基线的全部 100 个 case：Tb₈Mg₄、Li₈V₄Ni₄O₁₆ 两个生成样例，加 98 个 MP-20 样本。
每例源 CIF SHA256 已复核，样本覆盖 96 个识别空间群和七个晶系。这批样本强调空间群覆盖，不是对原训练分布的无偏随机估计。

encoder 获得晶体学事实，包括独立轨道、晶格和必要的坐标转换/精度信息，使用自然段自由组织空间叙述。
decoder 的请求只包含通用语义解码说明和该例生成的正文；没有原 CIF、事实包、材料 ID 或 encoder 对话历史。
语义 decoder 输出有限结构计划，固定程序查询公共 Hall/Wyckoff 表、进行数值计算并写出 CIF。

两个案例试点只覆盖标准输入框架。本轮扩展了坐标转换与精度修正接口，并在发起 API 调用前对全部 100 个输入进行了 oracle 几何预检，100/100 通过。
oracle 计划没有提供给 decoder，目的仅是确认数值接口能表示这些输入。

| 输入情况 | case 数 | 首次通过 | 其中连接失败 |
|---|---:|---:|---:|
| 无晶胞框架转换 | 29 | 26 | 1 |
| 需要晶胞框架转换 | 71 | 58 | 2 |
| 无逐原子精度修正 | 83 | 72 | 1 |
| 需要逐原子精度修正 | 17 | 12 | 2 |

两组分类有交集，不能相加作为不同样本集合。

## 失败的具体情况

| case | 首次失败阶段 | 观察到的问题 |
|---|---|---|
| mp-1173947 | encoder 传输 | 代理连接中断，无模型响应 |
| mp-558828 | encoder 传输 | 代理连接中断，无模型响应 |
| mp-1189636 | decoder 传输 | SSL EOF，无完整响应 |
| mp-1105932 | decoder 输出解析 | 返回了带 Markdown 围栏的 JSON |
| mp-11192 | Hall 符号处理 | 用 Unicode 下标写 `P 6₄ 2 (0 0 2)`，程序没有规范化该拼写 |
| mp-1215249 | 位点约束 | 代表坐标与 `1d` 位点不一致 |
| mp-353 | 位点约束 | 代表坐标与 `4c` 位点不一致 |
| mp-764280 | 位点约束 | 代表坐标与 `4h` 位点不一致 |
| mp-1218490 | 精度修正定位 | 舍入后无法按原地址定位修正原子 |
| mp-1099786 | 精度修正定位 | 舍入后无法按原地址定位修正原子 |
| mp-1224444 | 原结构匹配 | 晶格误差 `2.40e-7 Å` |
| mp-38220 | 原结构匹配 | 晶格误差 `4.10e-7 Å` |
| mp-1173526 | 原结构匹配 | 坐标误差 `2.0880e-5 Å` |
| mp-1223282 | 原结构匹配 | 坐标误差 `8.4733e-6 Å` |
| mp-546757 | 原结构匹配 | 坐标误差 `7.1999e-6 Å` |
| mp-555984 | 原结构匹配 | 坐标误差 `6.0913e-6 Å` |

这些是当前链路的失败，不应全部归因于 LLM 不理解空间关系。以下诊断只读已保存结果，没有新增模型请求，也不改变主结果。

### 真实的信息丢失：微小不等被写成完全相等

mp-1224444 的输入边长为 `(7.79230124, 7.79230124, 7.792301)` Å，生成正文写成 `a = b = c = 7.79230124 Å`。
decoder 因而恢复相同的三条边长，偏离原 c 值。
mp-38220 也出现同类情况：输入 c 为 `6.76399903 Å`，正文将其与 a、b 一并写成 `6.76399944 Å`。
这说明自然叙述中的理想化/概括会丢失严格恢复所需的小差异。

### 真实的信息丢失：精度偏差被概括成数量级

mp-1173526 的正文给出一部分精度修正后，将另一些硫原子的位移概括为“on the order of 10⁻⁶”，没有逐一保留分量。
decoder 仍输出完整计划，并给出与事实不同的修正值，最终不能恢复原输入。
因此 encoder 的信息完整性与 decoder 对欠确定描述的识别都需要改进；一个流畅段落并不自动成为可逆编码。

### 执行器的舍入敏感性

mp-1218490 与 mp-1099786 的未舍入几何骨架相对于数值 oracle 仅相差约 `2.23e-15`、`4.91e-15 Å`。
舍入后，差异却变为 `5.57e-6`、`8.56e-6 Å`，导致精度修正的地址匹配失败。
这是当前数值执行/舍入接口对微小浮点差异敏感的证据，不能将这两个案例简单记为语义恢复错误。
该诊断没有修复流程或将它们改为通过。

### 两个纯接口诊断

- 对 mp-1105932，仅去掉 JSON 外层 Markdown 围栏后，原计划能严格恢复原结构。
- 对 mp-11192，仅将 Hall 符号的 Unicode 下标数字规范化为普通数字后，原计划能严格恢复原结构。

二者都不改变任何晶格、坐标或描述内容，但属于事后诊断，**没有并入 84/100 的首次主结果**。

## 调用量与证据

## 当前结论

该模型与提示在本固定 cohort 上实现了 84/100 的首次严格结构恢复，说明真实 LLM 自然描述与盲语义解码能够处理相当一部分输入。
它还没有达到这批样本上的稳定全恢复。后续应分别检查明确的信息遗漏、近似等值表达、数值舍入与原子指代，以及输出接口，而不是把所有失败视为同一种模型能力问题。
本轮只报告恢复原结构的主实验，尚未验证自然性评分、等义改写稳定性、跨模型泛化、学习收益或物理稳定性。
