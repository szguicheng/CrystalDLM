# 计数块的实际槽位成本对照

固定 17 槽位的计数块诊断（532998）没有显示明确匹配率收益：50.244% vs RLE 50.000%，配对区间跨零，平均 profile NLL 略差。因此不扩大相同固定槽位模型的训练。

本实验回答尚未测过的问题：使用编码真正需要的槽位上限，是否降低计算成本，并保持或改善条件预测质量？

- RLE 用 9 槽位/元素，计数块用 6 槽位/元素，来自两者**同一完整候选库**的最大编码长度，不来自待预测结构的真实词数。
- 两者保留同样的 17 行位置参数表和 499,776 参数；只改变实际参与计算的槽位数量。
- 使用相同训练结构、候选集合、初始化种子、2,000 步、batch32、优化器、验证结构和合法读出。mask 比例分布相同，但槽位形状不同，不声称逐位置随机掩码一致。
- 两者同时重训，独立结果目录 `compact_word_runs/`。不把不同实验的最佳模型混成同一对照。
- 主质量指标仍是合法读出的整结构匹配率，检查点按 profile NLL 选择。实际总训练/验证耗时和 GPU peak allocation 一同报告。

单次 wall time 差异可能来自系统噪声；单种子、单次计时均不能证明稳定收益。若有正向信号，至少用另外两个固定种子复核，并在模型/超参冻结后评估保留测试集。纯非劣结论需预先声明容忍差，不能把无显著差异当成等效。

## 2,000 步开发结果后的固定复核预算

533026 的计数块 NLL 为 0.84375，RLE 为 0.88603；差 −0.04228，配对结构区间 [−0.06307,−0.01967]。匹配率差 +1.025 个百分点，区间跨零。峰值 GPU allocation 82,947,072 → 70,092,288 bytes；训练总时间均约 32 秒，没有速度优势。

额外的训练频率 sanity baseline（533030）在相同验证集上达到 60.06% 匹配率、0.65535 NLL，高于两种 2,000 步模型。因此不以小预算结果单独推荐该方案。

固定下一轮为同架构各 10,000 步、每 1,000 步验证、其他设置保持一致，输出 `compact_10k_runs/`。先复核 seed17；若 NLL/质量和资源优势继续存在，再补固定 seed29、43，后者交替训练顺序以减少顺序影响。最终测试模型数据在方法/预算与检查点选择规则冻结后才读取。

该实验仍为小模型和枚举候选读出，不代表大规模无枚举扩散、连续几何或物理稳定性。以此作为更完整研究方向的低成本筛选，而非宣称材料生成问题已解决。
