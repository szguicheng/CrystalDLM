三、inline 编码方案
流程：可信 facts→LLM 自由空间叙述及 typed placeholder refs→程序在原句位置填 <param>→encoder gate→盲 decoder→decoder JSON/schema gate→公共几何执行→评分。
推荐让 LLM 决定句子和段落组织，引用事实占位符；程序负责精确值和属性转录。占位约束不是固定 prose 模板。缺失、重复、未知引用判失败，不自动附加漏掉的参数。正文中的错误空间事实仍须检查。

保护字段：
1. cell 六参数或原始 basis 二选一，取决于保真合同；不要重复存两套。保存微小差别，不能概括成完全相等。
2. Hall 符号、独立 orbit 的元素、Wyckoff、自由坐标、稳定 orbit ID。公共表可推出的固定坐标与对称操作不重复。
3. 非 identity 原始 frame P 与 shift；必要 round_digits。
4. residual 全部三分量、坐标系及稳定 expanded-site 引用。
5. 必要 composition、原晶胞原子数等结构约束。
属性携带类型、单位、frame、ref；仅边界标签不足以区分数值用途。数值采用 float64 可读最短往返十进制，不用 hex 位串。这保护转录，不证明浮点变换或残差加法逐位精确。

冻结公共展开→frame 变换→round→mod→correction 的执行顺序和版本，忠实核对旧后端实际语义。稳定 site ID 必须由版本化公共 orbit 展开、原 frame 选像与顺序规则定义；建立 orbit 与展开位点映射。不能把旧浮点坐标地址改个名字当 ID，也不能偷传源原子表帮助 decoder 定位。

五、校验与已知失败
encoder 先检查标签语法、schema、refs、必需事实完整性与源 facts 的 value-match，通过后才请求 decoder。decoder 只看这一份 inline 文档和公共规则，严格 JSON/schema 通过后才进入 geometry；fenced JSON 判失败。source facts 只用于 encoder 验收与最终评分，不能 oracle 修补 decoder。

针对旧失败：mp-1224444 的微小晶格差曾被 a=b=c 概括；mp-1173526 的 residual 曾被“on the order of 10^-6”概括；纠正地址会受浮点路径与舍入影响；还有 JSON fence、Hall 下标字符等格式问题。标签、完整三分量、稳定引用和严格 gate 分别处理这些错误面。形式合法但值错误或漏事实仍失败，不能宣称 tag 自动100%。
