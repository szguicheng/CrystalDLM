# Periodic polyhedra-sharing extraction

Method ID: `crystal-polyhedra-sharing-20261012-v1`. The exact software pins, geometry tolerance, source-method digest, and schema are recorded in [sharing-method.json](sharing-method.json). Each augmented row stores the method ID and hash under `local_structure_facts.polyhedra_sharing`.

The extractor reads the already PLaID-decoded pymatgen structure and the stored coordination environments. It reuses the frozen geometry-only CrystalNN settings from `crystal_preannotation_20261012/feature-method.json`; it does not re-encode structures, recalculate labels, or change core facts. Package versions and the source feature-method hash are checked before a file is processed.

Each center with at least four CrystalNN neighbors gets a convex hull over those periodic neighbor positions. A hull is usable only if it is three-dimensional, every unique neighbor is a hull vertex, and the center lies strictly inside the hull. Coplanar, duplicate, interior-neighbor, and center-outside cases are marked ambiguous per center. A stored orbit motif is reused only when the recomputed center element, coordination number, and neighbor element counts match that site; otherwise its sharing output marks the motif unsupported. This retains reliable unnamed coordination hulls with explicit CN and verified motif metadata. `bcc` and `cp` remain local-arrangement labels and never imply a cube or cuboctahedron name.

Periodic vertex identity is `(site_index, image)`. Candidate polyhedron pairs are generated by joining shared neighbor site indices, then deriving center translations from image differences. The pair count includes distinct center sites in the reference cell against all candidate images; self-orbit translations retain one lexicographic orientation so each undirected periodic pair is counted once.

Qhull triangulates coplanar facets, so the extractor merges simplices by the periodic vertices lying within `1e-5 Å` of the same supporting plane. It projects each merged facet to two dimensions to recover only polygon-boundary edges. One shared vertex is a corner only when a strict separating plane through that point places the hulls on opposite sides. Two common vertices are an edge only when they form a hull edge in both polyhedra and a strict separating plane through the segment exists. Three or more common vertices count as a face only when the entire common set is the same merged facet in both hulls and the centers lie on opposite sides. Failed feature or overlap checks are counted as ambiguous and excluded from corner/edge/face totals.

The row distinguishes `computed` (including a real zero count), `not_applicable` (no CN≥4 centers), `ambiguous` (eligible centers but no valid hull), and augmentation `error`. A row-level sharing error does not change the source row status or erase its core facts and labels. The compact summary groups pair counts by center-orbit pair and includes up to two concrete examples per sharing type, with center element/motif/CN, shared vertex elements and periodic images, and the center-image translation.

Robocrystallographer provides the relevant standard periodic-neighbor convention: its `SiteAnalyzer.get_next_nearest_neighbors` compares periodic `(site index, image)` neighbor sets and uses common-neighbor counts to name corner-, edge-, and face-sharing connections. This extractor follows that periodic identity convention while adding explicit convex-hull edge/facet and non-overlap checks before emitting those labels. Its connectivity graph describes geometric coordination-hull contacts; it does not assert chemical bonds, oxidation states, or a framework type.

## Primary implementation references

- Robocrystallographer [`SiteAnalyzer.get_next_nearest_neighbors`](https://hackingmaterials.lbl.gov/robocrystallographer/_modules/robocrys/condense/site.html) shows periodic image-aware common-neighbor counting for corner/edge/face connectivity.
- Pymatgen [`CrystalNN` / `get_nn_info`](https://pymatgen.org/pymatgen.core.html) documents periodic neighbor image locations; the implementation is pinned to [Pymatgen v2025.10.7 source](https://github.com/materialsproject/pymatgen/blob/v2025.10.7/src/pymatgen/analysis/local_env.py).
- SciPy [`ConvexHull`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.ConvexHull.html) supplies hull simplices and supporting-plane equations; [`linprog`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.linprog.html) checks strict corner/edge separation feasibility.

## Running

```bash
research/plaid_20260930/.venv/bin/python research/crystal_sharing_20261012/augment.py \
  --input research/crystal_preannotation_20261012/full_002/shard-000.jsonl \
  --output /path/to/new/shard-000.jsonl
```

The CLI streams plain or gzip JSONL, preserves non-`ok` rows, writes atomically without overwriting an existing output, and prints a summary of row and sharing counts. `--limit N` supports bounded local checks. Each full shard can be augmented independently; no Slurm submission, API request, or full-population computation is part of this local implementation step.
