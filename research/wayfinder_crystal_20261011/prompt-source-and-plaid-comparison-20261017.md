# 结构请求来源与 PLaID++ 公平对照建议

日期：2026-10-17。用户确认逐项检查结构有效、结构条件、ehull、生成间重复和参考库重复；提出固定低 ehull（例如 0–80 meV/atom），每请求尝试 100 次。本文落实研究建议，未构造新训练集或启动模型。

## 澄清：训练验证集与生成基准不同

用户指出新结构生成不需要逐条复原验证晶体，这一理解正确。PLaID 的 `llm_finetune.py` 会加载 `val.csv` 并作为 Trainer 的 `eval_dataset`，采用按步评价；但论文 SUN/SSUN 主实验是独立采样后评分，不是对该验证集逐条预测唯一目标结构。

下文 295 个重合 ID 的统计仍成立，但“先排除重合，才能构造生成请求”的表述过强：若请求仅提取空间群或组成等部分条件，来源材料见过并不会自动使生成评价无效。新颖性应通过实际生成结构与共同参考库比较；请求条件本身可以在训练中出现。605/231 只能作为另做未见来源或泛化实验的候选池，不是主生成基准的必要筛选条件。主线应先固定一套有代表性、可行的设计请求，再评价新候选产率；只有专门声称未见材料/未见条件组合泛化时，才需要相应的留出与排重协议。训练验证集继续服务训练监控，最终生成评测请求独立固定。

证据：[官方训练代码](https://github.com/andaero/PLaID/blob/9ac91f07a263594bbaef1574efbf483a98152f0c/llm_finetune.py#L302-L323)、[生成评价 §5.1–5.2](https://arxiv.org/html/2509.07150v4)。

## 论文版本与指标

最新 arXiv 为 [2509.07150v4，2026-06-11](https://arxiv.org/abs/2509.07150v4)。此前笔记明确分析的是 v1；后续比较应固定 v4 和实际运行的代码/权重版本。

v4 主表仍报告无条件稳定率 22.27%、SUN 7.74%。SUN 的稳定判据为 ehull≤0；空间群条件 SSUN 要求指定空间群并采用≤0.1 eV/atom。0.08 eV/atom 出现在 DPO 偏好构造，不能当作主表 SUN 的阈值。无条件采样 10,000 个可解析结构；七空间群各 1,000 个；不可解析会重采。因此与固定 100 次原始尝试的分母不同。来源：[§5.1–5.3、Appendix 7.2](https://arxiv.org/html/2509.07150v4)。

v4 还增加体积模量目标实验（Table 2）和外部 LeMat-GenBench 评价（Appendix 7.4）。不同参考库与评价器会改变 SUN，主表百分比不能移植到 GRACE 评分下作为基线成绩。论文和发布资产进一步核对见 [PLaID benchmark evidence](plaid-benchmark-protocol-20261017.md)。

## 我们的 80 meV 任务

- 采用“结构要求＋固定低 ehull 筛选”是合理的首轮任务。这里将用户“给定一个结构”理解为给定结构特征要求；不额外引入完整 CIF 输入或结构编辑任务。
- 建议主门槛写为 ehull≤0.08 eV/atom。若评价器报告相对固定参考凸包的带符号距离，负值不应因低于 0 被排除；保留原始值，明确定义参考凸包，单独检查异常能量。
- 同一批评分同时报告 0、80、100 meV/atom 三个门槛；80 为项目主指标，0/100 为对照口径。只统一门槛不等于复现原论文，评价器、参考集合和分母也必须一致。
- 每个请求固定 100 次随机采样，用不同随机状态；不能用同一个 greedy 结果复制 100 次。失败仍占一次预算。每请求内结构等价类计一次，汇总同时报告请求平均、全局去重候选数和至少成功一次的请求比例。
- 100 次可作为先导比较。正式结论再根据观察到的差异和不确定性增加采样，不预先承诺胜过 PLaID。

## 请求从哪里来

### A. 论文共有的空间群基准

先采用 PLaID 的七个空间群：1、15、38、119、143、194、216。这里直接给空间群条件即可，不需要某个参考 CIF 来提供唯一答案。首轮每群 100 次，每模型共 700 次。相同语义的空间群 prompt 不因换了一条来源材料或换个措辞就算成新的独立结构要求。

该基准最接近作者已经验证的条件任务。使用其原生输入模板，不强迫 PLaID 输出我们的前后文字格式。固定低 ehull 是双方共同的结果筛选标准；是否加入显式性质提示、使用哪个等价模板需要先在开发请求上确定。不能把它的精确数值条件模板填 0.08 就声称实现了区间条件。

### B. 从我们的保留集事实构造更具体的请求

优先组合化学式与空间群；之后再加入可靠的配位和连接特征。事实由程序从已固定结构提取，模板直接生成英文，LLM 只做等义改写。来源结构是一个参考可行解，不向模型暴露完整坐标，也不要求模型复原它。

本次直接读取本地冻结数据，得到：

| 我们冻结的验证材料 | 900 |
| 与 PLaID basic/train.csv 材料 ID 重合 | 295 |
| 无精确训练 ID 重合 | 605 |

路径：`research/crystal_training_preflight_20261013/data_001/val-triples.jsonl.gz`、`work/PLaID/data/basic/train.csv`；PLaID 本地版本 `9ac91f07a263594bbaef1574efbf483a98152f0c`。主智能体用 Python gzip/json/csv 独立重算上述数量。

231 是候选来源数，不是已确认的 231 个不同且 GRACE 达标的请求：尚未排除不同 ID 的等价结构、按条件语义去重或在共同评价协议下确认可行性。不会改变旧 split/manifest，而是新增派生 benchmark manifest。开发用验证集；最终论文结果留给未用于调参的测试请求。

当前事实表具有组成、元素数、空间群/晶系、晶胞原子数、独立轨道数、Wyckoff 信息、晶格、体积、密度等字段。旧有局部环境/共享关系资产可供后续筛选，但不因“有字段”就自动纳入首轮共同基准。

### C. 丰富自然语言约束作为扩展任务

配位、多面体、角/边/面共享等要求可以体现我们的语言条件设计价值。但 PLaID 当前采样接口只直接提供 formula、spacegroup、ehull、bandgap 条件。不能把它未验证的长描述接口表现直接归因于 AR 架构较差。

可报告公开模型零样本迁移结果，明确接口适配方式；要研究训练方法差异，则使用相同条件数据训练匹配纯 AR，并与共享 AR＋diffusion 比较。

## 比较必须统一的部分

1. 相同请求语义和每请求尝试数。模型使用各自正确的输入/输出格式；采样超参数在开发集选择并冻结，给予相同调参预算。
2. 相同 GRACE 权重、弛豫、能量修正、参考凸包与适用域。对弛豫后结构重新核查条件；0/80/100 三门槛共用评分结果。
3. 相同结构匹配设置和新颖性参考集合。建议至少覆盖双方训练结构并固定版本；“相对训练集新颖”与“相对完整已知材料库新颖”单独命名。
4. 相同失败处理与去重口径。原始尝试全计分母；论文式重采结果如需复现另表报告。对唯一性的实现先核对：本地 novelty.py 的单例判断与“重复类只保留一个”不能默认等同。
5. 相同硬件下另报成本。公开 PLaID++ 经多轮 DPO，而我们当前配方是 SFT；与公开模型比较是最终系统能力对比，不能单独证明 diffusion 的收益。架构结论仍靠匹配纯 AR 对照。

## 最小后续顺序

先冻结七空间群共同请求与 80 meV 主口径，核实公开 PLaID 权重恢复链；准备小规模生成及共同 GRACE 评分检查。另行准备从保留集派生的组合条件请求，检查重合和可行性。工程预检通过且请求协议确定后，再运行双方固定预算对比。当前尚无 PLaID 实际生成成绩。
