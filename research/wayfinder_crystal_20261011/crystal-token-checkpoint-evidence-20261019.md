# Crystal diffusion checkpoints: CrystalDiT and DynaCrys

Primary-source check, 2026-10-19. Scope is architecture, model initialization evidence, structure representation, and a downloadable generator checkpoint. No weights were downloaded and no training was run.

| Method | Generator architecture and initialization evidence | Crystal representation | Public diffusion-generator checkpoint |
|---|---|---|---|
| **CrystalDiT** ([paper](https://arxiv.org/abs/2508.16614); [official repository](https://github.com/hanyi2021/CrystalDiT)) | Unified DiT: 18 blocks, width 512, 8 heads; 23 slots combine 20 atom slots and 3 lattice vectors. The denoiser predicts Gaussian DDPM noise for continuous lattice and atom features (1,000 steps); predicted period/group coordinates are decoded to elements afterward. The repository constructs a new `CrystalDiT` with Xavier initialization and only loads weights when `--resume` is supplied. | **DynaCrys** ([paper](https://arxiv.org/abs/2608.07401)) | Two generators: (1) an 8-layer, width-512, 8-head set denoiser for coupled symbolic diffusion; (2) a 6-layer, width-512 atom-level message-passing geometry diffusion model that generates lattice and coordinates conditioned on the symbolic result. The paper documents a separately trained, frozen symmetry codebook, but does not identify an external pretrained generator base or explicitly establish scratch initialization for either diffusion generator. | Symbolic state is space group `G`, orbit count `K`, and an unordered multiset of `(element, Wyckoff row)` occupations. Wyckoff rows are represented during diffusion by noisy 128-dimensional learned codebook vectors, not serialized language tokens. ## Decision-relevant read

For a readily obtainable, end-to-end crystal diffusion generator, **CrystalDiT is the verified option**: the weights file exists as a first-party Hugging Face artifact and the official README gives a generation command. Its structural representation remains continuous atom/lattice features, so it does not test learned discrete crystal-token diffusion. DynaCrys is the closer symmetry-native discrete/continuous hybrid: it diffuses space group, Wyckoff occupations, and elements symbolically, then generates geometry, but its learned symmetry codebook is a descriptor-derived embedding table rather than a learned structure tokenizer; its generator checkpoint is currently unverified.

## Primary evidence

- CrystalDiT paper: [arXiv paper](https://arxiv.org/abs/2508.16614) (representation and architecture); [AAAI proceedings PDF](https://ojs.aaai.org/index.php/AAAI/article/download/37121/41083) (reported training setup).
- CrystalDiT implementation: [official `crystal_dit.py`](https://raw.githubusercontent.com/hanyi2021/CrystalDiT/main/crystal_dit.py) (embeddings and initialization); [official `train_crystal_dit.py`](https://raw.githubusercontent.com/hanyi2021/CrystalDiT/main/train_crystal_dit.py) (model construction and optional resume loading); [README](https://github.com/hanyi2021/CrystalDiT/blob/main/README.md) (download and generation instructions); [Hugging Face files](https://huggingface.co/xiaohan-yi/CrystalDiT/tree/main).
- DynaCrys paper: [arXiv HTML](https://arxiv.org/html/2608.07401), especially §§4.1–4.4 and Appendices C, D, F. It states the symbolic protostructure and noisy row vectors, codebook construction/pretraining/freezing, diffusion models, and model training settings.

**Uncertainty boundary:** no model tensor was fetched or loaded. CrystalDiT artifact existence is verified by the first-party file listing and API metadata; successful inference from that file was not tested. DynaCrys initialization lineage and any post-publication checkpoint release remain unknown.
