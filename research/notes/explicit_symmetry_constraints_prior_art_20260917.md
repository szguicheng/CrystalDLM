# Explicit affine-constraint / generator-token crystal representations: prior-art audit

Date: 2026-09-17 (Asia/Hong_Kong)

Scope: primary-source audit of a proposed crystal tokenizer that replaces opaque Wyckoff letters/site IDs with (i) minimal affine coordinate constraints such as x=0, y=0, z free or x=y, z=1/4, (ii) independently named continuous parameters, and (iii) a small explicit set of Seitz/coordinate-map space-group generators. The proposed serialization has no per-atom edge list. This note does not inspect or modify experimental code and does not make a global novelty claim.

## Conclusion first

Several ingredients are already established separately, and two recent sources are especially close:

* **CrysTune** (search-indexed excerpts from the official OpenReview PDF for §3.1, §3.2.3, §3.3, and Appendix C3) keeps a space-group/Wyckoff label in the generated string, but explicitly teaches coordinate templates, snaps pinned coordinates such as (0,0,1/4), and expands a representative through affine maps W_j r = R_j r+t_j. This covers template constraints plus affine orbit expansion, but not a label-free constraint token stream. The official PDF/page could not be fetched as a local full-text artifact because OpenReview returned its browser challenge/API 403.
* **Matra-Genoa** (§II.1, §II.2, §IV.2) uses an invertible tokenized Wyckoff sequence with optional free coordinates; it reports a shared vocabulary of 990 algebraically distinct Wyckoff positions. This covers discrete site identity plus continuous parameters, but still uses Wyckoff identifiers and does not expose a small generator set as the site-level representation.
* **CLOUD/SCOPE** (§“SCOPE crystal representation”, Methods) already uses a minimal generator string for each space group and tokenizes generator symbols individually. Its occupied-site part remains Wyckoff symbols and composition, and the released converter emits no free coordinate variables in the reduced representation. This covers global generator tokens, but not explicit per-site affine constraints or independent parameter names.
* **DiffCSP++** (§4.2) and **PGCGM** already use affine operation maps/matrices to impose or expand Wyckoff-compatible coordinates, but they are diffusion/GAN geometry mechanisms rather than a symbolic tokenizer. **SLICES-PLUS** serializes symmetry operations as strings, but its core representation remains an edge-index/periodic-image graph and its symmetry part enumerates all operations, not a minimal generator set.

Therefore do not claim “first explicit affine symmetry constraints,” “first Wyckoff expressions/free coordinates,” “first affine orbit expansion,” or “first generator-string tokenization.” A cautious, narrower proposal-level boundary is:

> In the sources read here, I did not find a complete *single generative tokenizer* that removes Wyckoff/site IDs and instead emits a canonical, invertible per-site affine-constraint schema with named independent continuous parameters, while also carrying a compact global Seitz-generator token set and reconstructing all equivalent sites without a serialized per-atom edge list.

That is a combination/serialization claim, not a crystallographic novelty claim. It is only defensible if the implementation really (a) removes the label lookup at generation time, (b) canonicalizes setting/origin/parameter gauges, (c) proves exact round-trip expansion, and (d) demonstrates a benefit over the label-plus-template baselines above.

## Candidate-specific assessment

The current prototype described for this audit uses a finite arithmetic prefix grammar (x/y/z, ADD/NEG/MUL, rational constants, and FREE(value)); it encodes each representative axis directly, carries the same style of grammar for a compact global generator set, closes the group arithmetically without a space-group/Wyckoff table lookup, and optionally preserves source-decimal ROUND precision with sparse residuals. A probe reportedly reconstructs YbBPt2 in space group 180 with three orbits of multiplicities 3, 3, and 6.

Relative to the sources above, the potentially defensible difference is the **label-free, table-free interface**: CrysTune, CrystalFormer, Matra-Genoa, CLOUD, and DiffCSP++ still use a Wyckoff/site identifier somewhere in the generation or decoding path; PGCGM and DiffCSP++ use affine maps as tensors/constraints rather than as a single symbolic prefix grammar; CLOUD has compact generator tokens but does not combine them with free-coordinate constraints. The arithmetic grammar itself, rational constants, affine closure, and orbit expansion are standard operations and should not be called new mathematics.

The ROUND/residual channel should be described as a precision-preserving implementation option unless it shows a measured representation benefit. It may be useful for separating exact pinned constraints from nonexact CIF decimals or intentionally lowered symmetry, but it creates a second canonicalization question: residuals must not silently change a declared symmetry or make two equivalent encodings compare unequal. Report round-trip error, residual sparsity, symmetry recovery before/after residuals, and behavior on noisy/nonstandard CIFs.

For this prototype, the key falsifiable claims are therefore: no hidden Wyckoff lookup; one canonical expression/parameter assignment per setting; exact closure of the finite generator set; reversible expansion to the full orbit; and lower or more stable token/parameter complexity than label-plus-template baselines. If any parser stage maps an expression back to a WP ID to decide legality, the claim should be weakened to “an explicit expression front-end over Wyckoff tables,” because that is much closer to CrysTune/DiffCSP++.

## Direct overlap by proposed component

### 1. Minimal affine coordinate constraints

The crystallographic content itself is standard Wyckoff/site-symmetry information. CrystalFormer already omits fixed coordinates from the loss and projects sampled coordinates; DiffCSP++ and PGCGM apply affine maps; CrysTune explicitly predicts and repairs templates such as (0,0,1/4) and (x,0,1/4). The distinction that remains potentially useful is **canonical symbolic serialization**: e.g. represent a site by an ordered constraint matrix/equality system plus a deterministic parameter basis, rather than by a letter that indexes a table.

### 2. Named independent continuous parameters

Matra-Genoa is the nearest generation baseline with discrete and continuous tokens, and CrystalFormer/CrysTune emit free coordinate values. None of the inspected methods makes the *independent parameter basis* itself a first-class canonical token object shared across sites (for example, explicitly naming u_0, u_1 and tying repeated occurrences through a constraint graph/equality map). This could be a narrow representation difference, but it must handle parameter gauge choices and origin/setting changes.

### 3. Compact Seitz/generator set

CLOUD/SCOPE already establishes a compact minimal generator string as a token stream and explains how its operation letters plus translation codes generate all 230 space groups. SLICES-PLUS serializes operation maps too, but enumerates the full operation set. A claim of “first generator tokens” is therefore false; the only remaining claim is generator tokens **combined with** the label-free affine site schema and used by a generative/invertible tokenizer.

### 4. No per-atom edge lists

CLOUD, WyFormer, CrystalFormer, CrysTune and Matra-Genoa do not serialize per-atom edges. SLICES/SLICES-PLUS explicitly do (edge_indices and periodic image labels), while SymmCD/SGEquiDiff use internal graphs but do not make graph edges the serialized crystal representation. The absence of edges is thus a design choice, not by itself a novelty claim.

## Defensible novelty boundary and required tests

The strongest safe wording at this stage is “we propose an explicit affine-constraint/token representation” or “a label-free affine-site serialization combined with a compact generator string.” Avoid “first” language until a broader search includes later 2026 work and non-ML crystallographic software.

To turn the narrow combination into a defensible contribution, report at least:

1. **Round-trip correctness:** constraint string + parameter values + generator string → exact full orbit/CIF; compare back to the source after canonical setting/origin normalization.
2. **Gauge/canonicalization:** demonstrate that origin shifts, equivalent settings, WP permutations, and algebraically equivalent parameter names map to one canonical sequence. CrysTune's canonicalization task and WyFormer's Euclidean-normalizer handling are direct baselines.
3. **Legality coverage:** all 230 groups and all occupied special/general positions; exact multiplicity, stabilizer, fixed-coordinate, and free-DoF checks. Report unsupported nonsymmorphic/glide/screw cases separately.
4. **Parameter independence:** prove that named free parameters are neither accidentally tied nor duplicated, and show how equations such as x=y or x=-y+1/4 are represented without a hidden WP lookup.
5. **Ablations:** (a) Wyckoff label + coordinates, (b) constraints only, (c) generators only, (d) constraints + generators, and (e) an edge-list baseline such as SLICES-PLUS. Keep model, data, and decode budget matched.
6. **Generation metrics:** exact reconstruction, symmetry/space-group recovery, legal-site rate, composition/multiplicity consistency, OOD space groups/settings, sequence length/token count, and decoding latency. Stability or property gains should be reported only after representation legality is isolated.

This audit covers the named methods and the direct affine/Wyckoff-expression/generator precedents above. It is a bounded reading set; absence from this note is not evidence that no other 2026 or unpublished implementation exists.
